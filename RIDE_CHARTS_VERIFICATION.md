# Ride detail chart verification

Open Ride history, select a completed/interrupted ride, and scroll below the basic metrics.
Three separate Canvas charts show trainer watts, heart-rate BPM and cadence RPM. Labels
support Chinese and English. X is monotonic elapsed time; its range includes the stored
session duration and last sample. Each plot shows its lower/upper Y values and units.

Data path: existing Room samples query -> RoomRideRepository.historySamples ->
HistoryViewModel -> pure buildRideCharts transformation on Dispatchers.Default -> Canvas.
Only the selected session is loaded. Loading/failure/retry states are explicit. No new
schema, dependencies, writes, BLE changes or service/recorder changes are involved.

Null/nonfinite values break only that metric. Consecutive elapsed timestamps more than
3,000 ms apart break all metrics. Real zeros remain points on the baseline; isolated
measurements are dots. Segments are split BEFORE reducing points, so reduction never
bridges gaps. Wall-clock adjustments do not distort the elapsed axis.

Downsampling uses 256 deterministic time buckets across the samples. Within each segment
and bucket it retains first/minimum/maximum/last points in time order, removing duplicates.
A continuous ride uses at most 1,024 points per chart. Additional gap boundaries are
retained even when this exceeds that budget; exact gap preservation takes priority.
Raw samples and summary metrics are unchanged. Very short gaps in long rides may be
smaller than a screen pixel; no zoom or detailed diagnostics are included.

## Physical acceptance

1. Open a previously saved ride and verify all three charts match its approximate ranges
   and full duration. Empty/all-null metrics should display No data / 暂无数据.
2. Record about ten minutes with trainer and HR connected. Vary pedaling effort/cadence,
   and coast briefly. Include Home/another app and a locked-screen period while pedaling.
3. End the ride, open its details, and verify traces span the background period. Actual
   stored zero watts must remain on the baseline, not turn into a gap.
4. In a separate test ride, temporarily switch the HR sensor off long enough for readings
   to become stale, then back on (subject to the existing bounded reconnect behavior).
   Its chart should leave a blank interval for null readings while trainer charts remain.
5. If a saved ride has a recording pause over three seconds, confirm no metric draws a
   connecting line across that interval. No gaps are injected into production data for testing.
6. Open a long stored ride (thousands of samples), scroll and rotate: charts must resize,
   stay responsive, and retain obvious effort peaks. Check both app languages.
